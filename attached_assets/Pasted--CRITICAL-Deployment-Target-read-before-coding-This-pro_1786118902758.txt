## What you MUST do while building
────────────────────────────────

1) Portable stack only
Prefer one of these (in order):
A) Vite + React (+ TypeScript) + static build (`npm run build` → `dist/`)
B) Next.js with static export OR Cloudflare-compatible deploy (no Replit-only adapters)
C) Plain HTML/CSS/JS if the site is marketing-only

Avoid locking us to Replit:
- Do NOT depend on Replit Always-On / Replit DB / Replit Secrets as the only backend
- Do NOT use Replit-specific modules, paths, or “repl.co” hardcoding
- Do NOT require a long-running custom Node server unless absolutely necessary
  (prefer static frontend + serverless API later)

2) Standard Node project layout
Use a normal repo root:
- package.json with scripts: "dev", "build", "preview" (or "start" if needed)
- README.md with local run steps
- .env.example (never commit real secrets)
- .gitignore (node_modules, .env, dist/build artifacts as appropriate)
- src/ or client/ for app code; public/ for static assets
- No absolute Replit paths

3) Environment variables
- All secrets/API keys via env vars
- Provide `.env.example` with every required key documented
- Code must work with Cloudflare/Hostinger env injection later
- Never hardcode API keys, DB URLs, or Replit URLs in source

4) Domain-ready
- Use relative URLs for internal links/assets
- No hardcoded https://xxxx.replit.app or repl.co domains
- SEO basics: title/meta, OG tags, favicon, sitemap/robots if marketing site

5) Backend (if needed)
Prefer migration-friendly options:
- Forms: Formspree / Resend / Cloudflare Workers / email API (document which)
- DB: Neon Postgres or similar managed DB (not Replit DB)
- Auth: standard OAuth/JWT approach, documented
If you use Express/Fastify temporarily on Replit, isolate API under `/api` or `/server`
and keep frontend portable so we can move API to Cloudflare Workers later.

6) Design handoff quality
- Mobile + desktop responsive
- Production-ready assets (not temporary Replit CDN-only paths if avoidable)
- Keep components/pages organized for Cursor editing later
